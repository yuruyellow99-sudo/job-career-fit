# BOSS 直聘数据接入

## 获取岗位样本

`boss-zhipin-scraper` 是可选的本机数据工具。需要实时查 BOSS 直聘时，从 Codex 当前可用技能中定位它，阅读该工具的 `SKILL.md`，使用其文档说明的本机运行方式与检查流程。候选人提供该工具导出的职位列表或详情 JSON/CSV 时，可直接使用该快照，并保留抓取日期。没有工具、未登录、遇到平台验证或无法读取岗位时，说明阻塞；可以用公开的雇主招聘页面或其他可读的招聘平台 JD 交付，按实际来源标注。

1. 先列出候选人可在 BOSS 直聘、智联招聘和猎聘复制的岗位搜索词。按城市将岗位名逐个提交到 BOSS 的搜索流程；首轮从相关性最高的词开始。候选人要求扩大样本时，使用 `--pages` 让搜索页继续加载后续结果，并补充贴近目标职责的同义词。可以从每个城市、每个关键词最多 3 页开始，按实际返回和候选人的范围调整。遇到登录或平台验证时，暂停采集。已有重点公司清单时，也可单独搜索公司名并核对官方招聘页。`--company` 仅对已搜到的结果做本地过滤。
2. 首轮保留岗位列表，把详情读取集中在可能匹配的样本。将原始输出保存在当前任务工作区，避免写入可公开发布的 skill 或仓库目录。按 `job_id` 去重，缺 ID 时按职位链接核对。区分同名岗位的公司、城市与职级。
3. 对照列表与详情，保留岗位原名、公司、城市或区、学历与经验、薪资原文、职位链接和采样日期。只有实际读到 JD 才总结具体职责；只有正面证据支持时才标为明确在招。职位页无法打开、仅在列表出现或来源较早时，注明对应状态。公司简称可能与品牌或雇主主体不同，必要时用官网核对。

## 薪资证据

- 直接导出的岗位薪资按原样保留，例如 `20–40K·15薪`，并记录 `salary_source`。`api` 且内容可读时，可作为该样本的岗位披露值。`api_empty`、页面乱码、来源未知或相互冲突时，标为未披露或待核实，保留原记录供复核。用户提供的截图或可读职位页面可独立作为来源并注明来源方式。
- 区分目标 JD 披露、相似岗位参考和市场汇总。岗位未披露时，优先找同城市、相近职责和职级的样本，注明差别。只有月薪与薪数明确时可作名义年化换算，并将固定工资、绩效奖金、股权和补贴分别说明。单条岗位薪资不可概括为该公司的普遍薪资。
- 公司年报或公告用于业务、政策适用与投资核验。招聘平台的公司规模或融资阶段标签可作为查找线索，具体投资事实仍按 [调研和评分规则](research-and-scoring.md) 交叉验证。

## 报告格式

先给岗位搜索词，再按城市列公司、业务线、岗位匹配理由、公开 JD 原名或建议询岗名、来源、招聘状态和薪资。可将「岗位公开披露」「相似岗位样本」「待核实」直接写入薪资列。开头注明实际覆盖的城市、关键词、加载页数、采样日期与来源。有实采时报告列表记录数、岗位 ID 去重后数量、有效薪资数和已读完整 JD 数。比较多轮时，区分本次新命中与平台新发布。若只读取公开网页或历史快照，注明实际来源。
